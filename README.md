# plc-fc9-review

西门子 PLC 程序的审查与修复方案。对象是一条 4 工位转盘扫码流水线上的 FC9（自动模块 RFID）。

> 本仓库仅用于个人作品展示；未经许可不得用于商业用途。任务要求截图来自课程材料，仅作说明；审查结论与修复文档为本人整理。

做法是拿任务要求的 PDF 和 PLC 程序导出逐网络对比，把不符合约束、会导致误动作的地方挑出来，每条给出网络号和具体改法。

打开 `fc9-fix-guide.html` 看完整文档，里面有分级表、修复前后的网络截图和修复后的流程图。

## 发现的问题

一共 8 条，按严重程度分级：

| # | 问题 | 位置 | 级别 |
|---|---|---|---|
| 1 | FC9 直接操作 `writedata` / `readdata` / 数据读取，违反任务约束（这三个量只允许出现在基础程序里） | OB1 + FC9 网络 2–7 | 严重 |
| 2 | 网络 9 的工位选择只有 `>0.0` 判断，缺 `<=0.0` 互斥条件，多工位同时有效时 MOVE 互相覆盖 | FC9 网络 9 | 严重 |
| 3 | 步骤 3 → 4 转换时没复位 Done 标志 | FC9 网络 13 | 中等 |
| 4 | 暂停时复位了触发信号，步骤 1 或 3 中途暂停后恢复可能卡死 | FC9 网络 16–17 | 中等 |
| 5 | 网络 10 的补足逻辑，需要确认计数器递增正确 | FC9 网络 10 | 低 |
| 6 | 「未读取到正常件」指示灯用 S 线圈串闪烁时钟，时钟为 0 时没有 R 指令，灯亮一次就不灭 | FC5 网络 28 | 严重 |
| 7 | 读取指示灯在 Done 之后才置位，而不是读取开始时，和写入灯不一致 | FC9 网络 12–13 | 中等 |
| 8 | 7 个监控指示灯只在自动模式更新，手动模式不刷新，但任务要求「包含在手动时」 | OB1 + FC5 | 严重 |
